One partial for every state — empty, queued, running, finished, failed, cancelled, abandoned — and its own swap target, the same self-contained-region idiom as `_comment_thread.html` and `_case_notes.html`. Rendering every state here is what keeps a POST reply and a poll from disagreeing: both go through `ai._render_panel`. POLLING CONTRACT (the `_job_status.html` / `_bg_task_status.html` rule): the `hx-trigger="every 3s"` is emitted **only while `is_active`**, so a finished run stops polling by itself. Getting this backwards leaves every viewer of an old job issuing a request every three seconds forever. SWAP CONTRACT: `hx-swap="morph"` + `hx-ext="alpine-morph"`. The value is **exactly `morph`**, with no `:outerHTML` suffix, and that is not cosmetic — it is the whole difference between this region updating in place and being rebuilt three times a minute. `htmx-ext-alpine-morph.js` matches `swapStyle === 'morph'` and nothing else. Give htmx `morph:outerHTML` and the extension declines it, htmx's `default:` branch finds no handler, and it falls through to `htmx.config.defaultSwapStyle` — **innerHTML**. Three things then happen at once, and all three were reported as bugs: every child is destroyed and recreated on each poll (visible flicker), the log 
 is a brand-new element so its
  scroll position resets mid-read, and — because innerHTML never touches the *outer*
  element's attributes — `hx-trigger="every 3s"` survives on a region whose replacement no
  longer carries it, so the polling never stops until the page is reloaded.

  A real morph updates the region in place: node identity survives, so scroll position and
  focus survive with it, and when the run finishes the poll attributes are morphed away and
  the polling stops. `tests/test_alpine_bindings_initialize.py` pins the spelling against
  the extension's own source, because every symptom of getting it wrong looks like a
  different bug.

  The model's answer is Markdown and goes through `rich_text()`, never a bare `| markdown`.
  That is safe because `app/markdown_render.py` is configured so unsafe output is never
  produced — `html=False` escapes raw HTML at the parser and `validateLink` rejects
  javascript:/data: URLs — rather than being scrubbed afterwards.
#}
