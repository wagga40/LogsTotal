{% from "intel/partials/_tag_chip.html" import tag_dot_class, alpine_tag_classes, alpine_tag_dot %} {# Tag picker. A chosen tag becomes a **coloured pill inside the field**, not a string of text — the Select2 shape. Typing a name nobody has used yet still works and is still an explicit act, with its own colour swatches. **It takes several tags.** The caller sets `tagCombobox({ max: N })`; the input stays in the field until N pills are in it, Enter/Tab/comma each commit one, and Backspace on an empty box removes the last. `max: 1` is a single-tag control, which is what the rename and merge fields want — those genuinely name one tag. Each pill carries **its own colour**, and the field posts two index-aligned CSVs. One colour for the whole field would repaint every existing tag picked into it, because a tag name carries one colour instance-wide. Why a pill rather than text: a tag *is* a coloured chip everywhere else in the app, and a field that renders it as plain characters makes "I picked the existing apt28" and "I am about to coin apt-28" look identical at the moment it matters. Coining near-duplicates is precisely what makes a vocabulary worthless. Why not a native : browser chrome renders it as plain text, so a tag's colour cannot be shown, counts only fit as a label hack, and there is no way to distinguish the two cases above at all. **The submitted value is a hidden input written imperatively**, never a bound `:value`. Several of these live in htmx forms, and htmx serialises a form synchronously inside the submit event while Alpine applies bindings on its own scheduler, so a binding can send the previous selection. Every state change calls `sync()`, so what is in the DOM is what the server gets. Call inside an element carrying `x-data="tagCombobox({...})"`.
