How to read this graph
{# Only under a job scope, and worth the words: the scope is not uniform, and an analyst who assumes it is will over-read a typed edge or a red node. #}
What "job #" scopes
Which nodes are here, and the job/finding edges between them — all from this job alone.
Typed relationships are not scoped. They are cross-job aggregates with no job column, and the only per-job record of them is incomplete for older edges — filtering through it would silently hide real relationships. So a typed edge here is a true statement about two entities this job saw, not a statement about this job.
Node colour is not scoped either. Worst severity, dominant tactic, enrichment verdict and case membership are properties of the entity everywhere you can see it. Position and structure are about the job; paint is about the entity.
The edges are not equal
Same job — named in the same log file. That is all it means, so it is hidden by default and never carries a path.
Same finding — named inside one Sigma rule match.
Typed relationship — read out of the events and directed: runs as, parent of, resolves to. The name is drawn along the edge; click one for its evidence and when it was observed.
Filtering never moves a node

Search, type chips, colour and severity change what is emphasised — nothing is ever re-laid-out underneath you, so you can keep narrowing without losing your place. Only the Layout buttons and Expand move things.

Getting around
  • Click a node or edge for details · right-click for actions
  • Hover a node to light its neighbours
  • Drag a node to pin it — it stays put through a Force layout
  • Expand (⇕, top right) gives the graph the whole window — the toolbar comes with it
  • Esc steps back out: menu, panel, full screen, path, selection, search
  • Right-click two nodes → Path: start / end here to see every shortest route between them
